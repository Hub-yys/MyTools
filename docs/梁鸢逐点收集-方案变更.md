# 梁鸢逐点收集 —— 方案变更（2026-10-12）

> ⚠ **这份文档推翻了前几轮的方向。** 用户重新拆了问题，
> 新拆法让前面积累的很多"难题"直接消失。
> 改代码前先读这份。

---

## 一、为什么换方向

用户原话（2026-10-12）：

> 不对，你太过于追究细节完全一致了，我给你个思路，
> 把 60 个梁鸢收集拆分，**一个一个来**，每次我只要完成这个梁鸢收集就行。
> 所以只要完成：我能不能根据视频，找到梁鸢的所在位置，
> 然后控制角色过去，然后收集该梁鸢。
> 但是会发生，我的游戏里可能不存在该梁鸢（我已经收集），
> **你还需要确认，我的梁鸢是否已经收集了？**

### 旧方向（已放弃）：整段视觉伺服

前四轮都在做"让机器逐帧跟着视频走"。实测结论：

| 实测 | 结果 |
|---|---|
| 描述子认「机位」不认「地点」 | 同地点不同机位只有 **0.20**，落在"无关帧"分布里 |
| 视频结构 | **28 段剪切拼的**，含骑摩托 / 飞行 / 爬山 |
| 按键表 | 只有 10 次 F，**一次空格都没有**（飞行不显示提示，学不到） |
| 锁定后跟踪 | ✅ 93% 可用、0 误定位（这条**是**有效的） |

→ 结论：**"跟"本身没问题，但"从哪一帧开始跟"卡死了**，
  而且视频根本不是一条连续轨迹（28 段 + 60 个收集点）。

### 新方向：60 个独立任务

```
把 60 个梁鸢拆成 60 个任务，一次只做一个。
每个任务回答四件事：

  ① 这个梁鸢在哪？      ← 从视频取
  ② 怎么过去？          ← 待定（见第四节）
  ③ 收掉它             ← 按 F
  ④ 收没收到？          ← ★ 已实测：接口能答
```

**新拆法让这些东西不再是障碍**：

* 28 处剪切 → **无所谓**（每个点独立）
* 骑摩托 / 飞行 → 只要知道"这段是骑车去的"
* 逐帧机位一致 → **不需要**（只要认出那**一个点**）

## 二、★ 实测：④「收没收到」**能判断**（接口里有）

`kuro_account.fetch_explore()` 的返回里**有「无主的梁鸢」这个独立分项**：

```
name = 无主的梁鸢     type = 67
```

跨 **5 个区域**，各自返回 ``progress``（百分比）：

| 区域 | 进度 |
|---|---|
| 玄方城 | **93%** |
| 方擎西峰 | **84%** |
| 落渊南丘 | **72%** |
| 玄幽东岳 | **80%** |
| 梦枢天罗 | **97%** |

**5 个区全部未满** —— 所以"你其实基本没收"，
而不是我之前误以为的"快收完了"。

证据：`_probe/explore_items.py`，原始数据 `_live/explore_dump.json`

### ⚠ 但接口**只给百分比**，不给绝对数

分项对象的字段**只有 4 个**（5 个区完全一致）：

```
icon / name / progress / type      ← 没有 "已收 N / 共 M"
```

### 试过反解每区总数 —— **没有唯一解**

用"总数 = 60"（视频标题）当约束，对 round / floor / ceil 三种
百分比显示方式分别求解：

```
round  → 0 个解
floor  → 0 个解
ceil   → 2 个解（不唯一）
```

→ 所以**不能**从百分比精确反推"每区几个、还缺几个"。
 需要**另一个来源**给分母（见第三节）。

证据：`_probe/solve_counts.py`，结果 `_live/liangyuan_solve.json`

## 三、★ 分母在哪：**视频里有精确计数**

第一轮 OCR 视频前言时读到过（`_probe/intro.py`）：

```
无主的梁鸢 0/12      取偶匣 0/3      方庭演武 0/2
危锁奇藏 0/4        静心座 0/1
```

**「0/12」这种就是精确计数** —— 视频给的是**分母**。

```
每区总数（视频的分母） + 接口的百分比 → 已收几个也能算精确
                                    → "还缺几个"完全确定
```

⚠ 已确认视频第 10 秒有这张清单（`0/12` 被读到过一次）。
  但**还没把 5 个区的分母都读全**（脚本 `_probe/intro_counts.py`
  已写好，跑的时候 OCR 被另一个扫描任务占着，超时了）。

## 四、⚠ 唯一没解决的：②「怎么过去」

这是新方案里**唯一还没想通**的一环。

* 视频给的是**画面**，不是坐标
* 接口**没有坐标字段**（只有 icon/name/progress/type）
* 用户画面上的任务指引是「前去送别穗穗 · **1146米**」——
  那是**任务点**，不是梁鸢

**待确认（要问用户）**：

1. 梁鸢在**游戏地图上有标记/图标**吗？
   * 有 → "过去"简化成"走到那个图标"，**不需要逐帧跟视频**
   * 没有 → 只能靠视频画面认路，那还是回到视觉问题
2. 视频里 UP 主是怎么找的？他有没有打开地图点标记？
